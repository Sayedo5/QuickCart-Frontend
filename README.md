# QuickCart Backend

REST + realtime API for the QuickCart delivery platform.
**The only project that connects to the database.** The mobile app and the admin
panel are separate projects that talk to this API over HTTP and Socket.io.

```
Expo mobile app ─┐
                 ├──► quickcart-backend ──► Neon (PostgreSQL)
Next.js admin  ──┘
```

## Stack

| Concern | Choice |
| --- | --- |
| Runtime | Node.js 20+, TypeScript |
| Framework | Express 5 |
| Database | Neon serverless PostgreSQL |
| ORM | Prisma 6 (migrations included) |
| Auth | Email OTP (Nodemailer) → JWT access + rotating refresh tokens |
| Realtime | Socket.io (order status, rider GPS, admin feed) |
| Uploads | Cloudinary (memory → stream, nothing written to disk) |
| Validation | Zod on every body and query |
| Security | helmet, CORS allowlist, express-rate-limit, bcrypt, role guards |

## Quick start

```bash
npm install
cp .env.example .env          # fill in DATABASE_URL, DIRECT_URL, JWT secrets
npx prisma migrate dev --name init
npm run seed
npm run dev
```

Full instructions, including where each environment value comes from, are in
[SETUP.md](./SETUP.md). The schema is documented in [DATABASE.md](./DATABASE.md).

```
  migrations/            generated by Prisma

  config/     env (Zod-validated), db (Prisma client), cloudinary
  controllers/ auth, account, catalog, order, rider, admin, upload
  routes/     one router per area, mounted under /api/v1
  middleware/ auth + role guards, Zod validate, error handler, rate limits, multer

```

## Endpoints at a glance

Base `/api/v1` (also `/api`). Full detail with example bodies is in the Postman collection.

**Auth** `POST /auth/send-otp` · `POST /auth/verify-otp` · `POST /auth/signup` ·
`POST /auth/admin/login` · `POST /auth/refresh` · `POST /auth/logout` · `GET /auth/me`

**Catalog (public)** `GET /stores` · `GET /stores/:id` · `GET /stores/:id/menu` ·
`GET /stores/:id/reviews` · `GET /search` · `GET /categories` · `GET /banners` ·
`GET /coupons` · `POST /coupons/validate` · `GET /settings/public` · `GET /content/faqs` ·
`POST /stores/apply`

**Account** `PATCH /users/me` · `POST /users/me/push-token` · `GET|POST /addresses` ·
`PATCH|DELETE /addresses/:id` · `GET|POST /payment-methods` · `DELETE /payment-methods/:id` ·
`GET /favourites` · `POST|DELETE /favourites/:storeId` · `GET /wallet` · `POST /wallet/top-up` ·
`GET /notifications` · `POST /notifications/read-all`

**Orders** `POST /orders/quote` · `POST /orders` · `GET /orders/my` · `GET /orders/:id` ·
`POST /orders/:id/cancel` · `POST /orders/:id/review` · `GET /orders/all` (admin) ·
`PUT /orders/:id/status` (admin/rider) · `PUT /orders/:id/assign-rider` (admin)

**Riders** `POST /riders/apply` (public) · `GET /riders` · `GET /riders/pending` ·
`PUT /riders/:id/approve` · `PATCH /riders/:id` · `PUT /riders/:id/location` · `DELETE /riders/:id`

**Admin** `GET /admin/stats` · users · stores · products · menu sections · categories ·
banners · coupons · reviews · FAQs · `GET|PUT /admin/settings` · `POST /admin/broadcast`

**Uploads** `POST /uploads?folder=products|stores|riders|banners|avatars|documents`

## Design notes

- **Money is server-owned.** `POST /orders/quote` and `POST /orders` recompute the
  subtotal from live product rows, apply the admin's discount percentages, the store's
  delivery fee, the platform fee and tax from Settings, then validate the coupon.
  The client never sends a total.
- **Card numbers are never stored.** The PAN is Luhn-checked, the brand detected from
  the IIN range, then only brand + last4 are persisted.
- **Order history is immutable.** Item names, prices and the delivery address are
  snapshotted onto the order, so editing a product or address never rewrites the past.
- **Status transitions are guarded.** No moving backwards, no leaving a final state, and
  no "picked up" without an assigned rider. Cancelling a paid order refunds the wallet
  atomically.
- **Every write emits.** Status changes and rider GPS go out over Socket.io and as an
  Expo push, and land in the customer's in-app notification list.
